# 052: One scene as a GIF

## Context

A video does not play inline in a pull request comment or a Slack message;
a GIF does. Milestone 7 asks for one scene, at most 15 s, captions burned
in, no sound, under 5 MB (7.2).

## Decision

- **Every render makes `scene.gif`** beside its poster, for each theme, so
  it always matches the video it came from.
- **The scene is the second when there is one, else the first.** That is the
  heart of most stories: the "after" of a change explainer (051), the "how it
  works" of the problem shape. The rule agreed first was "the scene the
  brief's takeaway lands in, else the last scene". It was dropped because the
  render does not read the brief, and finding the scene a free-text takeaway
  lands in would need the LLM or a new field; the last scene was the
  fallback, but in a change explainer the last is What to review, the least
  telling to watch. So the rule is the storyboard's alone.
- **It runs from the scene's first beat to the last beat that ends within
  15 s**, so it never stops mid-beat; a first beat longer than that is cut
  at 15 s. The times come from the same beat plan as the render's.
- **It is cut from `video.mp4`**, so the captions are burned in as in the
  video. The sound is dropped.
- **Aiming under 5 MB**: ffmpeg makes a palette for the clip (from the parts
  that change), redraws only what changes from frame to frame, and tries
  smaller sizes until one fits. When none does, the smallest is kept, as the
  best there is. The length, the size, the colours and the sizes tried are
  in `src/schema/render.ts` (`GIF_LIMITS`, `GIF_SIZES`), beside the render's
  other shapes; no LLM drafts a GIF, so they need no zod schema of their own.

## Alternatives

- **A GIF on request only** (a tool or a button). Fewer seconds per render,
  but one more step, and a GIF that can drift from its video.
- **A setting for the scene.** Possible later; the rule fits the shapes the
  guide teaches.
- **WebP or MP4 loops.** Smaller, but GitHub comments and Slack play only
  GIFs inline everywhere.
